# Food Context Protocol Governance

## Principles

1. **Meritocracy** - Contributors advance based on their actual contributions
2. **Ecosystem Health** - Protocol serves the broader food AI ecosystem, not individual companies
3. **Transparency** - All decisions are documented publicly
4. **Consensus** - Decisions by majority vote when possible

## Roles

### Contributors

Anyone who signs the Contributor License Agreement (CLA) can contribute code, documentation, or specification changes.

**How to become a contributor:**

- Sign the CLA (automated via GitHub bot)
- Submit pull requests or participate in discussions
- All contributions are welcome

### Maintainers

Developers who review pull requests, maintain releases, and manage documentation.

**Current Maintainers:**

- @jwegis (Founding Maintainer)

**How to become a maintainer:**

- Sustained contributions over 3+ months
- Demonstrated understanding of protocol design
- Nominated by existing maintainers
- Approved by Technical Council

### Technical Council (TC)

Responsible for:

- Technical decisions and architecture
- Specification changes
- Roadmap planning
- Maintainer selection

**Current Members:**

- @jwegis (Founding Member)

**Future Expansion:** TC will grow to 5-7 members based on sustained contributions to the protocol.

**Meetings:** Monthly, with agendas published 24 hours in advance and minutes within one week.

### Governing Council (GC)

Oversees protocol health, adoption strategy, and long-term vision.

**Current Status:** Self-governed during incubation phase

**Future:** GC will form when 3+ organizations adopt FCP in production. The GC will include representatives from adopting organizations and ensure the protocol serves the broader ecosystem.

## Decision Making

### Specification Changes

1. **Proposal** - Open a GitHub Discussion with:
   - Problem statement
   - Proposed solution
   - Example use cases
   - Impact analysis

2. **Community Feedback** - Minimum 2-week discussion period

3. **TC Review** - Technical Council reviews and votes

4. **Vote** - Majority rule (simple majority for minor changes, 2/3 for breaking changes)

5. **Implementation** - Update specification, schemas, and reference implementation

6. **Documentation** - Update docs and announce changes

### Code Changes (Reference Implementation)

1. Contributors submit pull requests
2. Maintainers review (require 1+ approval)
3. TC members have final say on architecture decisions
4. Automated tests must pass (100% coverage enforced)
5. Merge to main branch

### Roadmap

- TC proposes quarterly roadmap
- Community feedback via GitHub Discussions
- GC approves strategic direction (when formed)
- Published on project board

## Transparency

All protocol discussions happen in public:

- **Discussions:** [GitHub Discussions](https://github.com/Food-Context-Protocol/fcp/discussions)
- **Issues:** [GitHub Issues](https://github.com/Food-Context-Protocol/fcp/issues)
- **Pull Requests:** All PRs are public
- **Meeting Minutes:** Published in [meetings/](meetings/) directory
- **Roadmap:** [GitHub Projects](https://github.com/orgs/Food-Context-Protocol/projects)

## Conflict Resolution

1. **Discussion** - Attempt to reach consensus through discussion
2. **Mediation** - TC member mediates if discussion stalls
3. **Vote** - If no consensus, TC votes (majority rule)
4. **Appeal** - GC can review TC decisions (when formed)

## Code of Conduct

### Our Standards

- **Be respectful** - Treat all community members with respect
- **Be inclusive** - Welcome diverse perspectives
- **Be collaborative** - Work together to solve problems
- **Be constructive** - Provide actionable feedback

### Unacceptable Behavior

- Harassment or discrimination
- Trolling or insulting comments
- Personal attacks
- Spam or off-topic content

### Enforcement

- **Warning** - First offense receives a warning
- **Temporary ban** - Repeated offenses result in temporary ban
- **Permanent ban** - Severe or repeated violations result in permanent ban

Report violations to: conduct@fcp.dev

## Amendment Process

This governance document can be amended by:

1. Proposal via GitHub Discussion
2. 4-week community feedback period
3. TC vote (requires 2/3 majority)
4. GC approval (when formed)
